# Portfolio Interview Mode

Portfolio Interview Mode is the reviewer-facing route at `/portfolio`. It is
designed for a technical interview or portfolio screen where the reviewer wants
to understand why ForgeML is an ML platform project, not a single-model demo.

## Reviewer Dashboard

The dashboard organizes six claims:

- Multi-project ML platform control plane
- Modular monolith with extractable boundaries
- Worker-backed queued training lifecycle
- External recommender adapter without platform coupling
- Observability, drift, alerts, and retraining loop
- Release-governance loop with audit evidence

Each claim points to code, contracts, tests, docs, or a product route. The goal
is to keep the conversation grounded in verifiable evidence instead of broad
claims.

## Architecture Walkthrough

The Architecture Walkthrough uses four stages:

- Control plane: FastAPI routes, application services, domain entities, and
  repositories.
- ML execution: training runner, external package profiles, artifact manifests,
  and MLflow gateway.
- Serving runtime: deployment revision resolution, serving gateway, inference
  logs, and health probes.
- Governance plane: security contracts, release manifests, evidence retrieval,
  and operational audit.

The recommended narrative is to explain why ForgeML starts as a modular
monolith, then point to adapter boundaries where workers, MLflow, artifact
storage, serving, and governance could scale independently.

## Evidence Explanations

The page highlights four evidence explanations:

- What proves this is not a toy project
- Where the ML engineering depth shows up
- Where the MLOps maturity shows up
- How to explain the architecture tradeoff

These map directly to `docs/portfolio/evidence-map.md`,
`frontend/tests/e2e/platform-lifecycle.spec.ts`,
`docs/runbooks/demo-readiness.md`, and `docs/architecture-walkthrough.md`.

## Validation Paths

Use these commands before a review:

```bash
make demo-stack-fresh
make demo-walkthrough
make demo-screenshots
make production-readiness
make portfolio-interview
PYTHONPATH=. python scripts/ci/check_portfolio_interview_mode_contract.py
```

Expected signals:

- Fresh local demo state with seeded project, release manifest, and release
  evidence refresh reports.
- Playwright coverage for `/portfolio`, lifecycle pages, Release Evidence, and
  Operational Audit.
- Screenshot evidence including `11-portfolio-interview-mode.png`.
- Production readiness and release evidence contract coverage.
- `portfolio_interview_mode_contract` present in CI and release manifests.

## CI Contract

`contracts/ops/portfolio-interview-mode.v1.json` is generated by
`scripts/ci/check_portfolio_interview_mode_contract.py`. The contract verifies
that the route, navigation item, page sections, docs, e2e walkthrough,
screenshot flow, and CI wiring stay aligned.
